Who gets rebooked first?

Late flights need ranking from the worst arrival delay to the best, and equal delays must keep their original file order. Four handwritten algorithms solve it. Watch them race on the same flights.

Every bar is a flight, colored by delay. Each lane runs the real algorithm and advances the same number of steps per frame, where a step is one comparison or one write. Counters use the same accounting as my_solutions.py.

Why ties are the hard part

Plain heapsort can swap flights that have the same delay. Your version breaks ties by original position. Flip the switch and sort the same flights both ways. Same color means same delay.

The recommendation

Which one to use depends on the key range and what you are short of.

Counting sort

Best fit here

Delays are small integers in a bounded range. 3.4 ms for 10,000 flights and 37 ms for 100,000. Costs extra memory as the range grows.

Mergesort

Safe for any range

Stable by construction and independent of the key range. 0.96 s for 100,000 flights. Needs about n extra slots.

Heapsort

Predictable and lean

Same speed on random, nearly ranked and reversed input (0.11 s at 10,000). Smaller peak memory than mergesort. Needs the position tie-break to stay stable.

Insertion sort

Small jobs only

Simple and light on memory, but it swings from 0.24 s to 17.8 s at 10,000 flights depending on the input order. Never the fastest in these runs.
